# LLM 점수화 코드북 (LLM Codebook)

- 버전: **v0.0 (초안)** · 상태: **미동결** (동결 전에는 대량 실행 금지)
- 목적: 신고 글을 구조화된 점수로 바꾸는 기준(항목 · 척도 · 앵커)을 사전에 고정한다.

## 1. 설계 원칙

1. **정형 컬럼과 겹치지 않는 정보만** LLM에 맡긴다. 사고 · 화재 · 부상 · 주행거리는 이미 컬럼이 있다 (겹치면 실험 C가 B와 같아진다).
2. 자유 점수 대신 **앵커(정의 + 예시)가 있는 소척도**를 쓰고, "판단 불가" 선택지를 둔다.
3. 판단마다 **원문 근거 문장**을 인용하게 한다 (경고 사유 요약에 재사용).

## 2. 항목

| 항목 | 값 | 앵커 (초안) |
|---|---|---|
| `potential_severity` | 0–3 | 0 불편 · 소음 / 1 경고등 · 기능 저하 (운행 가능) / 2 주행 중 출력 · 제동 · 조향 일부 상실 / 3 화재, 완전한 동력 · 제동 · 조향 상실, 에어백 오작동 |
| `failure_modes` | 다중 라벨 | `fire_smoke`, `propulsion_loss`, `braking`, `steering`, `electrical_12v`, `airbag_restraint`, `unintended_accel_shift`, `other` |
| `recurrence` | 0 / 1 | 수리 후 재발, 정비소 "원인 불명 · 재현 불가" |
| `specificity` | 0–2 | 부품 · 증상 · 상황이 얼마나 특정되는가 (신뢰도 가중치) |

- 위험도 앵커의 참고 후보: ISO 26262 중대도 분류(S0–S3), FMEA식 중대도 정의 (김종건 외, 2025). **아직 대조하지 않음.**
- 예시 문장(앵커별 2–3개)은 파일럿 샘플에서 골라 이 문서에 추가한다. TODO

## 3. 출력 스키마

```json
{
  "potential_severity": 2,
  "failure_modes": ["propulsion_loss"],
  "recurrence": 1,
  "specificity": 2,
  "unscorable": false,
  "evidence": {
    "potential_severity": "<원문에서 인용한 문장>",
    "recurrence": "<원문에서 인용한 문장>"
  }
}
```

## 4. 입력 마스킹 (사전지식 누수 방지)

평가 구간(2022–2025)이 LLM 학습 기간 안일 수 있어, 모델이 알려진 리콜을 "알고" 점수를 줄 수 있다.

- 점수화 전에 제거 · 치환: 브랜드, 차종, 연식, 날짜, VIN, 딜러명, "recall" · 캠페인 번호 언급
- 마스킹 전후 점수를 비교한다.
- 프로브: "이 글이 어느 리콜에 해당하는지 맞혀보라"로 누수 정도를 측정한다. TODO

## 6. 검증 프로토콜

- 사람 라벨 약 200건: **개발 50 / 검증 150**. 코드북 수정은 개발셋에서만 한다.
- 일부(약 100건)는 2명이 겹쳐 라벨 → 사람 간 일치도(가중 κ)를 먼저 구한다.
- LLM과 사람의 일치도가 사람 간 일치도에 가까우면 충분하다고 본다 (기준선: 사람 간 일치도).
- 층화 추출: 화재 · 동력 상실 같은 드문 사례를 일부러 포함한다.
